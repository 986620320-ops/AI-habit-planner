# Prompt 链 03：从固定大学生定位改为通用 AI 规划

- **时间**：2026-10-26
- **相关提交**：`10379d7`
- **核心问题**：作品最初写死“大学生”人群，不适合真实评审和通用产品定位。

## 1. 用户原始 Prompt 链（原文）

> 其实我觉得大学生的定位也不太好你，我想面向不同群体

> 你不能给个通用模板，让ai自行判断人群吗，还是说你这是mork模式下的模板

> 改为通用 AI 规划 + 可选补充信息 + AI 自行判断人群。

随后用户提交了一份完整实施计划，核心要求包括：

- 不写死大学生、中学生或固定人群模板。
- AI 根据已有习惯、积分和可选补充信息判断最接近的场景。
- 信息不足时生成中性通用方案，不强行猜测身份。
- Mock 模式明确显示“通用示例”，不伪装成真实人群判断。
- 前端增加最多 200 字的补充信息，保存到 localStorage。
- 服务端 Prompt 将补充信息作为背景，并提醒模型不要执行其中的指令。
- AI 返回 `audience` 短标签，例如“备考学生”“职场效率”“健身自律”“生活规律”“通用”。
- 保留三阶段进度、打字机、真实/Mock 和额度逻辑。
- 更新 README、PROJECT_STATUS 和测试回归。

## 2. AI 建议

- 把“人群分类”从硬编码 UI 改为 AI 的推断结果。
- 用户补充信息默认可选，空值时使用中性方案。
- Mock 和真实模式必须明确区分，Mock 不得声称自己完成人群判断。
- Prompt 中把用户输入标记为背景数据，降低 Prompt 注入风险。
- 把 audience 限制为短标签，避免模型输出长段落或不稳定分类。

## 3. 实际修改

- 增加 `context` 输入、字数统计、清空和本地保存。
- 服务端改为通用习惯规划师 Prompt。
- 模型输出增加可选 `audience`。
- 前端展示“AI 判断场景”，Mock 模式展示“Mock 示例（通用）”。
- 通用推荐习惯改为早起、喝水、运动、阅读、早睡。
- README 和状态文档同步更新。

## 4. 验证

- 无补充信息时可以生成通用方案。
- 有补充信息时请求体携带 `context`，Prompt 中包含背景。
- `audience` 空值、超长和异常输入能安全处理。
- Mock 模式不伪造人群判断。
- 三阶段进度、打字机、额度和积分功能回归通过。
- 前端与 API 脚本语法检查通过。

# Prompt 链 02：删除习惯积分漏洞与 20 个习惯上限

- **时间**：2026-10-26
- **相关提交**：`b2b492f`
- **核心问题**：用户在使用中发现积分刷分漏洞和前后端习惯数量上限不一致。

## 1. 用户原始 Prompt（原文）

> 我发现两个个问题  一，删除习惯时清掉了打卡记录和连续奖励，但积分总额和流水还在；重新添加同名习惯后还能再次打卡得分。二，前端没有限制习惯数量，服务端最多处理 20 个

## 2. AI 分析与修改建议

- 复现路径：添加习惯 → 多次打卡 → 删除习惯 → 重新添加同名习惯 → 再次打卡，导致历史积分未扣回。
- 根因：删除习惯只清理了打卡和连续奖励，没有扣除该习惯贡献的积分及流水归属。
- 修复策略：
  - 给旧积分流水补写 `habitId`，避免仅依赖名称。
  - 删除习惯时计算该习惯贡献的净积分。
  - 新增 `type: 'delete'` 扣回流水。
  - 删除时最多扣到 0，不产生负积分。
  - 前端增加 `MAX_HABITS=20`，与服务端保持一致。
- 同时检查删除习惯后重新添加同名习惯时是否会恢复旧积分。

## 3. 实际修改

- 增加旧流水 `habitId` 回填逻辑。
- 增加 `getHabitPointContribution()` 计算习惯历史贡献。
- 删除习惯前显示实际扣回额度。
- 删除后清理打卡、照片、奖励归属和积分。
- 前端第 21 个习惯被拦截；服务端仍保留 20 个上限作为第二道防线。

## 4. 验证

- 余额 70、习惯贡献 20：删除后余额 50，新增 `delete` 流水 `-20`。
- 重新添加同名习惯后余额仍为 50，不能再次刷分。
- 余额低于贡献值时只扣到 0。
- 第 21 个习惯被前端拦截并提示“最多只能添加 20 个习惯”。
- 其他习惯的积分流水不受影响。

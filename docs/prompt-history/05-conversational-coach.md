# Prompt 链 05：一键规划改为连续对话式 AI 教练

- **时间**：2026-10-30
- **相关提交**：`269d715`
- **核心问题**：一次生成整份规划的交互不像真实 AI，无法追问、记忆上下文或自然导入习惯。

## 1. 用户原始 Prompt（原文）

> 那个一键生成对话形式改成可以像正常ai一样对话的形式

随后用户确认了“AI 规划改为连续对话式习惯教练”实施计划，具体要求：

- 支持消息气泡、上下文记忆、追问、快捷问题和新对话。
- 最近 30 条消息保存在本机，刷新后继续对话。
- 真实 AI 每次只携带最近 12 条真实模式消息。
- AI 推荐习惯时显示候选卡片，可单个或全部导入。
- 默认 Mock；真实 AI 每日 10 轮对话。
- 第 11 轮只提示额度用完，不自动切换 Mock。
- 切换模式不清空聊天记录。
- 回复完整返回后逐字显示，不使用真实流式接口。
- 用户消息失败时保留，可重试。
- 新对话取消未完成回复。
- 聊天记录写入备份/恢复文件。
- 继续维护单个 `index.html` 和 `netlify/functions/api.js`。

## 2. AI 给出的方案

- 使用本地 `ai-habit-checkin:ai-chat` 保存最近 30 条消息。
- 将 AI 卡片改写为聊天面板，包含欢迎语、三个快捷问题、输入框和发送按钮。
- 真实请求改为 `action: 'chat'`，最多携带最近 12 条真实模式消息。
- 服务端返回结构化 JSON：`reply`、`audience`、`habits`。
- 聊天记录与 Mock 记录都带 `mode` 字段，真实请求过滤 Mock 上下文。
- 额度桶使用 `chat`，兼容旧的 `plan` 字段；默认 10 次。
- 错误信息作为系统气泡展示，保留用户原始消息并提供重试。
- 聊天记录包含在备份 JSON 中。

## 3. 实际修改

- 新增聊天样式：消息区、气泡、候选习惯卡片、输入中状态。
- 新增 `loadChat/saveChat`，限制 30 条。
- 新增请求 token 与 AbortController，新对话可取消未完成请求。
- 新增 Mock 关键词回复，不调用模型。
- 新增失败重试和额度手动切换 Mock。
- 增加聊天记录备份与恢复。
- 删除旧的一次性规划流程和补充信息大文本框。
- 更新 README 和 API 文档。

## 4. Bug 与修复链

- 首次浏览器回归发现模型返回规划测试为空，原因是旧测试服务没有模拟 `action: 'chat'`；AI 将前端请求明确加上 `action: 'chat'`，并验证服务端默认规划兼容。
- 为验证“新对话取消旧请求”，增加 Mock 延迟请求回归，确认 token 能阻止旧响应写入新对话。
- 为验证“额度用完不自动切换”，模拟第 11 次 429，确认页面仍显示真实 AI，并提供“切换 Mock 继续”按钮。
- 为验证历史上限，注入 35 条消息并刷新，确认存储和 DOM 都只保留 30 条。

## 5. 验证

- 多轮对话、快捷问题、刷新恢复、新对话和旧请求取消通过。
- Enter 发送、Shift + Enter 换行通过。
- 单个/全部导入、重复过滤和 20 个习惯上限通过。
- Mock 模式不产生 API 请求。
- 真实模式第 11 轮 429，不自动切换。
- 手动切换 Mock 后继续对话且不增加 API 请求。
- 备份恢复包含聊天历史。
- 375px 和 1440px 无横向溢出，无运行时错误，无重复 ID。

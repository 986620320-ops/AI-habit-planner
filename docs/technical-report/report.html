EXECUTIVE SUMMARY

作品摘要

AI HABIT COACH / 02

很多习惯工具解决的是“如何生成计划”，却没有解决“计划进入真实生活后如何被理解、反馈和持续调整”。

核心定位：AI 不只是规划器，而是理解上下文、接受自由证据并持续对话的习惯教练。
01

连续对话

最近 30 条消息保存在本机，真实请求携带最近 12 条真实模式上下文。

02

自由证据

照片、文字或语音转文字均可；不要求用户手写随机口令或摆拍固定物品。

03

可信降级

AI 不确定时追问一次；仍无法判断时可填写复盘手动完成，两种方式都获得积分。

AI HABIT COACH / 03

习惯失败通常不是因为用户不知道目标，而是因为计划无法适配每天变化的场景。

AI 习惯教练 · 技术报告06 / 18
INTENT CONTROL

意图控制策略

AI HABIT COACH / 07

意图控制不是写更长的 Prompt，而是把“目标、约束、状态和验收”拆成可执行的多层结构。

01

任务层

明确用户要解决的真实问题，禁止为了演示而加入无效复杂度。

02

边界层

不改 API 路径、不泄漏 Key、不破坏积分和 20 个习惯上限。

03

状态层

把 localStorage、IndexedDB、额度、Mock/真实模式和旧数据迁移写清。

04

验收层

每个改动都给出成功路径、失败路径、回归路径和可复现命令。

典型反例：“把页面做得更好看”不可验证。
本项目写法：“保留 #checkin/#shop、默认 Mock、真实 AI 第 11 轮 429、手动完成 +10、375px 无横向溢出、备份恢复聊天记录”。

当问题从“手写识别失败”变化为“需要新的证据模式”时，AI 首先重新定义问题，而不是继续优化错误的 OCR 路线。

AI 习惯教练 · 技术报告07 / 18
CONTEXT DESIGN

上下文与 Prompt 设计

AI HABIT COACH / 08

对话上下文

只保存最近 30 条；真实 AI 请求只发送最近 12 条真实模式消息；Mock 消息不会污染真实模式上下文。

单条边界

用户消息最多 500 字；服务端会再次截断证据文字、补充信息和追问回答。

可信状态

当前习惯、连续天数、累计天数和积分由前端随请求附带，服务端只作为背景使用。

不可信数据

习惯名、聊天文本和证据文本都被标记为不可信内容，不能执行其中的指令。

{"action":"chat", "messages":[{"role":"user","content":"我最近总是熬夜"}], "habits":[{"name":"阅读","streak":2,"totalDays":8}], "totalPoints":30, "today":"2026-10-30"}

服务端返回结构化 JSON：reply、可选的 audience 和最多 5 个 habits。解析失败时明确提示重试，不静默使用未经约束的文本。

AI CONVERSATION

连续对话接口与结果

AI HABIT COACH / 09

请求路径

前端通过 action: "chat" 请求 Netlify Function，服务端再调用 DeepSeek。

POST /.netlify/functions/api { "action": "chat", "messages": [ {"role":"user","content":"帮我制定规划"} ], "habits": [...], "totalPoints": 0 }

返回结果

聊天回复与习惯卡片分开，前端只使用纯文本渲染。

{ "reply": "建议从每天十分钟开始...", "audience": "生活规律", "habits": [ {"name":"睡前放松","icon":"🧘"} ], "quota": {"chat":{"limit":10,"remaining":9}} }

追问

模型只在信息不足时提问一次，用户回答后禁止再次追问。

导入

候选习惯由用户点击后写入本地，不由模型直接修改列表。

额度

第 11 次返回 429；页面保留对话，用户主动切换 Mock。

BUG FIX

典型 Bug：删除习惯后的积分漏洞

AI HABIT COACH / 14

用户报告：删除习惯后，历史积分和流水仍然存在；重新添加同名习惯后还能再次得分。

根因拆解

删除只清理打卡和连续奖励；旧流水没有稳定的 habitId 归属；重新添加同名习惯后，历史贡献仍可能被误算。

修复动作

补写 habitId → 计算贡献 → 写入 delete 流水 → 最多扣到 0 → 前端限制 20 个习惯。

验证结果

通过：余额足够时扣回贡献；余额不足只扣到 0；重新添加同名习惯不恢复已扣积分；第 21 个习惯被拦截。

REPRODUCIBILITY

可复现性论证

AI HABIT COACH / 16

评委可以从空白骨架开始，按 README 在 10 分钟内完成 Mock 体验，再用环境变量开启真实 AI。

Mock 路径

Python 静态服务器 → #checkin → 快捷问题 → 习惯导入 → 文字证据 → 积分商城。

无需 API Key 或 Netlify CLI，适合快速检查界面和交互。

真实 AI 路径

复制 .env.example → 填写 Key → netlify dev → health → 真实对话/证据。

所有函数位于 netlify/functions/api.js，部署路径固定。

依赖

浏览器、Python 3.10+、Git；完整模式需 Node 20 LTS 与 Netlify CLI。

验收

健康接口、Mock/真实切换、连续对话、证据打卡、积分和备份。

故障

项目可见性、函数 404、密钥扫描、额度用完和本地数据清理。

复现不是“能看到页面”，而是能解释每个数据、每个请求和每个失败路径。

LIMITATIONS

限制、风险与后续规划

AI HABIT COACH / 17

当前限制

无账号和跨设备同步；额度为进程内计数；积分仍在本机；没有真实流式输出；照片会发送到真实模型服务。

架构取舍

单文件前端优先解决比赛复现和部署成本；服务端函数集中权限与模型调用；正式产品应拆分模块和服务端账本。

下一步 1

将额度和积分迁移到 Netlify Blobs / Redis。

下一步 2

增加账号和加密同步，支持多设备。

下一步 3

实现真正的流式响应和可中断工具调用。

设计底线：AI 失败不能阻断用户完成当天记录；手动复盘必须可用；密钥和用户数据不能进入 Git。
